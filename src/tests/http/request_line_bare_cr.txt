#  RFC 9112 §2.2: "A recipient of such a bare CR MUST consider that element
#  to be invalid".  A bare CR (not immediately followed by LF) embedded in
#  the request line must be rejected, not silently absorbed into the path.
#
#  This is caught by fr_http_length() in the TCP transport, before the
#  message is ever handed to a worker, so the connection gets a real
#  "400 Bad Request" response rather than being silently dropped.
#
#  Request (raw bytes):
#    GET /pa<CR>th HTTP/1.1\r\n
#    \r\n
#
#  Expected: 400
#
#  CMD: bash -c "exec 3<>/dev/tcp/127.0.0.1/PORT; printf '\x47\x45\x54\x20\x2f\x70\x61\x0d\x74\x68\x20\x48\x54\x54\x50\x2f\x31\x2e\x31\x0d\x0a\x0d\x0a' >&3; head -1 <&3; exec 3>&-" | cut -d' ' -f2 | tr -d '\r\n'
